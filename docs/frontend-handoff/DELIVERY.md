## Экранные задачи

### Карта и список площадей

- Карта — основная рабочая поверхность. Выбранная площадь видна в списке и на карте.
- Один набор общих дат на все площади; видимое число пригодных сравнений.
- Инспектор показывает изменение, качество, действие; не набор несвязанных KPI.
- Поиск по R-коду и переключение слоя работают без потери масштаба/площади.
- Приблизительность контуров видна рядом с контекстом, подробности раскрываются.
- «Нет пригодных данных» получает самостоятельный стиль, не зелёный статус нормы.
- Мобильная панель не перекрывает единственную точку/кнопку выбора на карте.

### Анализ и место

- До/после имеют одинаковые масштаб и легенду; разделитель управляется мышью,
  касанием и доступным альтернативным контролом.
- Изменение NDMI/NDVI написано с датами и единицами; покрытие подписано как покрытие.
- Выбор точки подтверждается маркером и коротким сообщением; вне обводки сервер
  возвращает понятную ошибку, старое место не сохраняется молча.
- После смены площади или пары прежний ответ API не должен перерисовать новый
  контекст: отменить устаревший запрос или проверить ключ перед применением.
- Главный CTA ведёт к вопросу для осмотра; для облачной пары он не создаёт
  задачу по основанию другой даты.

### Задача, история, выезд

- Ответственный и вопрос обязательны; плановая дата необязательна. Пример текста
  не выдаётся за введённую пользователем запись.
- При сохранении кнопка сообщает прогресс; неопределённый сетевой исход можно
  безопасно повторить тем же запросом. Успех — только после ответа сервера.
- После сохранения открывается история нужного места. План выезда необязателен.
- Форма реального посещения и предпросмотр для защиты различаются явно.
- Ограничения фото видны до выбора файлов. Текст не пропадает при ошибке размера.
- Временная шкала различает съёмку, создание задачи и фактическое время осмотра.
- Сохранённое основание остаётся неизменным при открытии нового архива.
- До трёх разных мест в плане; это список обследования, не оптимизация дороги.

## Что можно улучшать самостоятельно

Композицию, типографику, отступы, зелёную палитру, компоненты, адаптивность,
состояния форм, тексты, навигацию, доступность, скорость повторного просмотра
и клиентское кеширование с корректным ключом версии/пары/места.

Научные пороги, оконную геометрию, маски, единицы, шкалу растров, правила качества,
алгоритм приоритета и определения исходов не менять внутри UI. Не добавлять
автоматические диагнозы. Новые фильтры и сортировки должны обозначать реальный
смысл существующих значений. Для новых серверных функций сначала контракт.

## Чек-лист приёмки

| Проверка | Ожидаемый результат |
|---|---|
| Чистый запуск на новом ноутбуке | Устанавливаются зависимости, проверяются 92 архива, открывается `/scouting` |
| Открытие приложения | Чтение данных не создаёт задач или посещений |
| Исходная осенняя пара | 26.09 → 11.10.2026, пригодны 27/27; данные не называются текущей съёмкой |
| Архивный пример R11 | 21.09 → 14.10.2026, ΔNDMI ≈ −0,119; пригодны 14/27; причина неизвестна |
| Весенняя пара | 12.05 → 27.05.2024, 13/27; пропуски остаются пропусками |
| Быстрая смена площади/дат | Нет старого изображения или числа под новым заголовком |
| Выбор места | Одно и то же окно в задаче, истории и экспорте |
| Неполная форма | Ошибка рядом с полем; введённое не теряется |
| Повтор сохранения | Одна запись при повторе неизменённого `request_id` и тела |
| Устаревшая версия | Сообщение о необходимости повторно выбрать основание, без тихой подмены |
| Недоступный сервер | Понятная ошибка и повтор; нет ложного сообщения «сохранено» |
| Пустая история | Предложение создать задачу; фото и результаты не генерируются |
| Предпросмотр посещения | Можно показать форму; сохранение факта недоступно |
| Реальная запись | Только после фактического осмотра и явного подтверждения; время с TZ |
| Фото | До трёх, не более 5 МБ каждое; ошибка не уничтожает заметку |
| Закрытие формы | Черновик текста/фото возвращается в той же странице; границы reload объяснены |
| План | 1–3 разных места; печать/JSON/GeoJSON содержат исходное основание |
| Переключение дизайна | Контекст и черновики сохранены, карта корректно меняет размер |
| Клавиатура | Фокус виден, диалог закрывается, фокус возвращается к вызвавшей кнопке |
| Телефон | Ключевые действия доступны без горизонтального скролла и перекрытий |

Технические POST-тесты выполнять только в `data/frontend-dev-journal` или
временной папке тестов. Тестовая запись не становится полевым наблюдением и не
используется в метриках. Рабочий журнал хозяйства и фото не добавлять в коммит.

## Команды технической проверки

Из корня репозитория, после первого запуска:

```powershell
py -3.13 scripts/start_scouting.py --check-only --no-install
.venv\Scripts\python.exe -m unittest tests.test_farm_workspace tests.test_farm_scouting tests.test_scouting_design
node --test tests/test_scouting_drafts.cjs
```

Node нужен только для последней проверки, а не для запуска продукта. Если выбран
новый стек, приложить его lock-файл, команды запуска/проверки и встроить их в
инструкцию. После изменения JS/CSS дополнительно пройти сценарий в браузере:
Python-тесты не проверяют удобство, размеры панелей и фактическую работу кликов.

## Материалы, которые вернуть вместе с UI

1. Коммит в этой ветке или дочерней ветке, список изменений и известные ограничения.
2. Обновлённый запуск с чистой копии и результаты подходящих проверок.
3. Настоящие скриншоты карты, анализа R11, задачи и предпросмотра результата;
   хотя бы один мобильный экран. Пары дат и версия записаны рядом.
4. Двухминутный маршрут показа: карта → пример → точка → вопрос → история →
   предпросмотр результата. Реальные осмотры для скриншотов не придумывать.
5. Примечания о недостающих API и список того, что осталось планом.

# Формат данных осмотров

Excel предназначен для ручной работы агронома; JSON — для фиксации выбора командой и отдельной технической проверки. Автоматического импорта Excel в приложение нет. Основной журнал выбирается заранее: не нужно вести одинаковые заметки в двух местах. Фотографии сохраняются отдельно в оригинале, с ID визита и контрольной суммой; ссылки в таблице не заменяют файлы.

## Фиксация раунда

Заполняется **до осмотров**, по пустому `round-template.json`. Один файл — один раунд. Исходный файл сохраняется неизменным вместе с SHA256 и временем сохранения; исправления — отдельная версия с причиной и ссылкой на оригинал. Одна лишь дата, введённая вручную, не доказывает время фиксации.

| Поле | Содержание |
|---|---|
| round_id | Уникальный ID раунда, не дата без указания хозяйства |
| decision_at_utc | Последний допустимый момент входных сведений; ISO8601 с часовым поясом |
| snapshot_saved_at_utc | Время сохранения полного снимка выбора, не позже decision_at_utc |
| rule_version | Версия заранее фиксированного правила/модели; не менять по результатам раунда |
| study_mode | prospective; ретроспективный анализ явно отделять |
| candidates | Полный пул мест, в том числе исключённых, а не только рекомендованные |
| pool_sha256 | SHA256 UTF-8 JSON массива candidates: sort_keys=True, ensure_ascii=False, separators=(',', ':'); helper `pool_hash` |
| system_top_k / routine_top_k | Упорядоченные списки place_id одинаковой ненулевой длины |
| routine_list_saved_at_utc | Когда сохранён независимый обычный выбор агронома |
| routine_list_before_system_seen | true только при реальном соблюдении порядка; иначе сравнение не независимое |
| selected_controls | Случайные place_id из остатка, без возвращения, до исходов |
| random_seed | Целое начальное значение генератора; дополнительно сохранить алгоритм/версию и полный порядок выборки |
| assignments | Один visit_id на уникальное выбранное место, пересечение списков посещается один раз |
| sources | Входные источники с временной доступностью и хешем |

Каждый элемент `candidates`: `place_id`, `field_id`, `geometry_version`, `boundary_status` (`confirmed` / `approximate_research`), `eligible` (boolean), `exclusion_reason` для исключённых, `source_ids` (массив). Кроме этих проверяемых полей команда сохраняет **геометрию места/окна WGS84 или ссылку+SHA256**, рассчитанные признаки с единицами, показатели облаков/пропусков и чувствительность к границе. У приближённой обводки нет подтверждённого ID хозяйства: использовать отдельный исследовательский идентификатор, не объявлять его реальным полем.

Элемент `sources`: `source_id`, `sha256` (64 строчных hex-символа), `acquired_or_issued_at_utc`, `available_at_utc`; дополнительно локальный путь, URL, версия продукта, processing baseline, единицы и маска качества. Оба времени не позже выбора. Для архивной перепроцессированной сцены сегодняшняя загрузка не доказывает доступность в прошлом. Если доступны лишь поздние источники, пометить исследование ретроспективным и не выдавать его за воспроизведение рабочего выбора.

Элемент `assignments`: `visit_id`, `place_id`, `inclusion_probability`; дополнительно срок, порядок предъявления, запланированная геометрия, прошлый визит, причина отмены и `supersedes_visit_id` для исправлений. Для объединения двух top-K вероятность 1; для m случайных из N оставшихся — m/N. Алгоритм случайного выбора и принадлежность спискам хранит команда, не показывает исполнителю до оценки. Проверяющий скрипт проверяет состав и вероятности, но не генерирует контроль и не удостоверяет честность рандомизации.

Подготовку списка системы и обычного списка измерять отдельно в минутах, в журнале раунда: `system_planning_minutes`, `routine_planning_minutes`. Эти поля не рассчитываются из времени посещений и пока не входят в автоматический отчёт. Полный пул, геометрию, признаки и время фиксации проверяет команда вручную: технический скрипт не является полной проверкой дизайна исследования.

## Результат визита и Excel

В `results-template.json` массив `results` первоначально пуст. Одна текущая версия на visit_id; историю исправлений хранить отдельно, не суммировать версии. Пустая строка Excel не является результатом визита.

| Excel «Осмотры» | JSON | Правило |
|---|---|---|
| ID визита / ID поля | visit_id / field_id | Связь с назначением и пулом |
| Осмотр: дата и время | observed_at_utc | Фактическое время, не плановое |
| Внесено: дата и время | recorded_at_utc | Не раньше посещения; исправления не скрывать |
| Широта / долгота фактическая | actual_lat / actual_lon | Числа WGS84; плановые координаты не копировать как факт |
| Код наблюдателя | observer_code | Устойчивый код участника; контакты хранить отдельно |
| Полнота осмотра | completion | Полный→full, Частичный→partial, Не удалось→unreachable, Отменён→cancelled |
| Что увидели | notes | Факт/подозрение/неизвестное различать словами |
| Новая информация | new_information | Да→true, Нет→false, Неясно/пусто→null |
| Нужен следующий шаг | followup_required | Те же boolean/null; шаг описать отдельно |
| Полезность осмотра | usefulness | Полезен→useful, Не дал новой информации→no_new_information, Неясно→uncertain, Не оценено→not_assessed |
| Почему / следующий шаг | usefulness_reason | Обоснование и следующий шаг, включая явное отсутствие необходимости |
| Осмотр / дорога, минут | inspection_minutes / travel_minutes | Неотрицательные числа, неизвестное null |
| Фото: файлы / ссылки | photo_refs | Массив ссылок на оригиналы; наличие фото само по себе не даёт метку |
| Операции: что известно | operation_note | Ссылка на журнал операций с временем доступности |
| Наблюдаемая фаза | observed_phase | Реальное наблюдение или null; не сезонный индекс под видом BBCH |
| Статус проверки | review_status | Не проверено→not_reviewed, Проверено→reviewed, Спорно→disputed |
| Код проверяющего | reviewer_code | Кто проверил полноту/обоснование; тот же автор не означает независимую экспертизу |
| Место сверено с планом | position_match | true только после ручной/геометрической сверки, иначе false/null |
| Метка проверена: время | label_available_at_utc | Когда оценка стала доступна после проверки; не раньше записи |

Все даты Excel вводятся как даты/время в МСК (UTC+03:00), а при подготовке JSON переводятся в ISO8601 с часовым поясом, например с суффиксом `+03:00` или `Z` после перевода в UTC. Текстовое время без пояса проверку не проходит. Вручную введённые времена нуждаются в проверке первичных источников.

У отменённого/непроведённого визита нет фактического времени и координат осмотра: оставить null, указать статус, причину и время внесения записи. Время проверки метки остаётся null до её реальной проверки. Не подставлять плановую дату или текущий момент вместо отсутствующего факта.

Поля «Поля» и «Операции» — отдельные реестры, не бинарная разметка. Для операции обязательны реальный ID поля, вид, время выполнения, время получения сведений, источник. Неизвестную культуру/дату не восстанавливать предположением. Повтор того же места получает новый visit_id при неизменном place_id; записи одной проблемы объединяются в event_id для разбиения данных.

## Запуск технической проверки

Из корня проекта:

```text
.venv/Scripts/python.exe -X utf8 scripts/check_inspection_priority_data.py docs/inspection-priority/round-template.json docs/inspection-priority/results-template.json
```

Пустые шаблоны дают `status=no_data`, 0 реальных раундов и исходов, показатели качества null. Неполный визит не становится 0. При нарушении состава, независимости списка, времени входов, вероятностей или дубликатах сравнительные показатели не публикуются. Для Precision@K нужны все K проверенных исходов обоих списков. Указанная `completion` — доля назначений с **пригодной проверенной оценкой**, а не просто число физически выполненных посещений.

Проверка одного раунда не строит доверительные интервалы по всему пилоту, не проверяет согласование, диагноз, авторство, реальные координаты, оригиналы фото, полноту геометрии/признаков и факт случайного выбора. Она не считает экономический эффект и не допускает продукт автоматически. Ошибочный раунд хранится для исправления, его provisional_labels очищаются. `training_allowed=false` всегда: это подготовка сбора и сравнения, не автоматический датасет для обучения.

# Показ AgroPulse перед жюри — 4–5 минут

Актуально для интерфейса `/scouting` после шлифовки 7 ноября 2026.
Показываем реальный архив и работающий процесс подготовки осмотра. Не выдаём
спутниковое изменение за прогноз болезни, а демонстрацию формы — за полевой тест.

## Подготовка

На новом ноутбуке остановить сервер, выполнить `git pull --ff-only`, запустить
`START_SCOUTING.cmd`. Открыть http://127.0.0.1:8770/scouting и заранее пройти
архивный пример: убедиться, что обе карты загружаются. Вернуться кнопкой «Карта».
Текущая версия берётся из Git; прежние ZIP со сборками содержат прежний интерфейс.

Для репетиции с отдельным журналом:

```powershell
.\START_SCOUTING.cmd --port 8776 --directory data/defense-rehearsal-journal
```

Адрес репетиции: http://127.0.0.1:8776/scouting. Свой журнал хозяйства и фото
переносить в эту копию не нужно. Чтобы начать новый чистый показ, используйте
новую папку журнала, а не удаление имеющихся записей.

проверить полезность этих задач на реальных выездах, а не обещать диагноз по одному индексу».

## Если есть ещё минута

В истории нажать «Включить в план выезда». Задача уже выбрана, название
«Осмотр R11» предлагается автоматически и редактируется. Нажать «Сохранить план»
→ «Скачать лист». В листе есть координаты, вопросы и основание; строки результата
остаются пустыми. Это последовательность до трёх мест, без оптимизации дорог.
Кнопка «Открыть задачу и историю» возвращает к записи результата.

Если спросят про дополнительные открытые данные: «Карта» → «Слой карты» →
«Рельеф поверхности» или «Почва · глина», затем «О площади». DSM включает
растительность/здания; SoilGrids имеет сетку 250 м. Это контекст для обследования,
не местный анализ почвы и не доказанная карта холодных карманов.

## Что действительно происходит при записи результата

После настоящего посещения: история → «Записать результат осмотра» → автор,
фактические дата/время (Москва), исход, наблюдения → при наличии фото и следующий
шаг → подтверждение реальности → «Сохранить результат осмотра». Запись появляется
в истории того же места. Для повторного посещения используется та же кнопка;
«Новая задача для места» создаёт новый вопрос, а не запись посещения.

Закрытие формы сохраняет её несохранённый текст и выбранные фото в памяти этой
вкладки. Обновление страницы их удаляет. Черновики задач и планов восстанавливаются
после обновления в той же вкладке. Сохранённые задачи/результаты/планы — в локальном
журнале; Git их не переносит.

## Не перепутать числа

- Начальная общая пара **26.09 → 11.10.2026**: 27/27 пригодных площадей,
  R11 ΔNDMI около **−0,077**.
- «Архивный пример» **21.09 → 14.10.2026**: 14/27 пригодных площадей,
  R11 ΔNDMI около **−0,119**, NDVI около **−0,173**, покрытие около **92%**.
- Эти числа — наблюдаемое изменение и доступность данных. Они не являются
  качеством прогнозной модели или доказанной экономией.

## Если что-то пошло не так

- «История» в навигации возвращает к задачам выбранной площади; выбрать нужную
  задачу слева. Она не показывает историю всех площадей одновременно.
- После случайного обновления формы задачи открыть её снова с теми же датами,
  индексом и подтверждённым местом: черновик привязан к этому основанию.
- На снимке клик вне допустимой обводки отклоняется. Для плавного показа используйте
  «Использовать точку с крестиком», не подбирайте положение на ходу.
- Если времени мало, пропустите план выезда и дополнительные слои: основной
  законченный путь — карта → изменение → задача → форма результата → история.

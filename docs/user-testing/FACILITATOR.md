# Комплект первого теста Onlyfarms

Подготовьте до пяти сессий по 20–25 минут. Папки P01…P05 — свободные места, не прошедшие тест люди. Используйте одну папку на человека и сохраняйте её для повторного раунда. Реальный сад не требуется.

## Запуск

В PowerShell из корня репозитория подготовьте новый комплект:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m agro_checker user-test-prepare --test-dir .\data\user-tests\round-01
```

Команда не перезаписывает существующую папку. Для дополнительных участников создайте комплект с новым названием и выдайте уникальные коды; не пересоздавайте папку человека для повтора. Подготовленный комплект уже содержит базы, шаблоны и `kit.json` с точными ночами, выдачами и контрольными суммами.

Запустите копию первого участника:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m agro_checker field-serve --state-dir .\data\user-tests\round-01\P01\state --port 8780
```

Откройте http://127.0.0.1:8780/ и нажмите «Пройти учебный сценарий». Для следующего человека остановите этот тестовый сервер Ctrl+C, замените P01 на P02 и снова запустите его. Перезагрузите страницу. Рабочий сервер8770 и его журнал остаются отдельными. Внешний сбор GFS и daily-shadow не нужны. Каждый сервер доступен только локально; ссылка127.0.0.1 не работает на компьютере удалённого участника. Для дистанционной встречи используйте демонстрацию экрана с управлением участником или отдельный локальный запуск. Ведущий, кликающий за участника, проверяет понимание, но не самостоятельное управление; отметьте это в условиях.

## Проведение

1. За 2 минуты объясните добровольность, учебный режим и отсутствие управления защитой. Запишите роль, постоянный код и согласованный способ использования цитат. Не показывайте участнику `kit.json`: там исходы ночей для ведущего.
2. Предъявите задачу1 из `PARTICIPANT_TASKS.md`, наблюдайте по `SESSION.md`. Основная оценка самостоятельности относится к первой задаче; задачи2/3 дополняют её и уже имеют эффект обучения. После первой ночи затруднения не стирайте.
3. Быстрыми кнопками последовательно выберите «Учебная ночь2» и «3». Не раскрывайте исходы до результата. Подтверждение просмотра и время решения относятся к текущему разбору архивной ночи, не доказывают реальное действие до заморозка.
4. На шаге результата заполните отзыв с типом «Проверка с пользователем» только при реальном участнике. При незавершённом задании откройте шаг сами после прекращения и выберите «Не удалось завершить». При самостоятельной проверке команды используйте инженерный тип и отдельный код.
5. Сохраните JSON отзывов из «Журнал и осмотры → Проверка прототипа» и экспорт журнала в папку человека, подпишите раунд. Запишите точные ID отзывов в `SESSION.md`. Решение участника ищите по его коду в поле ответственного и ID выдачи.

Синтетические исходные решения «Демо-оператор» сохраняются для проверки ночей и отмечены как сценарные. Их ID перечислены в `kit.json`; это не решения участников. Участник может увидеть их после открытия результата — зафиксируйте это как ограничение следующих задач. Копии не содержат решений других участников. Не объединяйте клонированные исходные события простым сложением: считайте отзывы по уникальному коду и сопоставимому раунду, исходные fixture-ID исключайте из пользовательского журнала.

## Исправления и повтор

После первого цикла заполните `CHANGES_TEMPLATE.md` реальными наблюдениями, выберите изменения, проверьте их инженерно. Затем откройте сохранённую папку того же человека и те же ID ночей, перезагрузите UI и проведите повтор. В отзыве выберите предыдущую запись. Обновлённый сервер использует текущий код, а старые выдачи и решения остаются в базе. Не меняйте прогноз ради улучшения результата.

Критерии: четыре из пяти проходят основную задачу без ведущего; повтор не оставляет путаницы между станцией и садом или порогом и повреждением; каждое существенное изменение связано с наблюдением и повтором. При меньшем числе участников сообщайте фактическое число и не объявляйте критерий выполненным. Полный протокол находится в репозитории: `docs/USER_TEST_PROTOCOL.md`. Интервью, готовность платить и экономика ведутся отдельно.

Если подготовка оборвалась, папка не является готовым комплектом без `kit.json`. Не использовать неполную копию; создать новый каталог и сохранить прежний для разбора сбоя. Для повтора использовать существующую папку, а не команду подготовки.

## Что показываем пользователю

Рабочий сценарий: **карта → реальные архивные изменения → явный выбор места →
вопрос в задаче → история места → фактический результат после посещения**.
План выезда составляется отдельно из сохранённых задач.

R01–R27 — приблизительные обводки, восстановленные по скриншоту, а не подтверждённые
номера полей. Цвет карты показывает изменение индекса; его нельзя переименовывать
в вероятность болезни, ущерб, срочность обработки или точность прогноза.

В этой ветке нет карточки `/api/scouting/review`, новых радарных данных,
автоматического обновления Sentinel-2 и интерфейса будущих выпусков из модельной
ветки. Не рисовать эти возможности как уже подключённые. Общий архив и текущая
съёмка — разные понятия; старую пару не обозначать как тревогу «сегодня».

## Основной путь

| Шаг | Действие | Что должно остаться согласованным |
|---|---|---|
| Карта | Выбрать площадь по обводке или списку; при необходимости найти код | Выбранная площадь, подпись инспектора, выделение на карте и дальнейший контекст |
| Архив | Выбрать период и общую пару дат | Одна и та же пара для карты, списка и карточки. Для непригодной площади — отсутствие сравнения, без скрытой другой пары |
| Снимки | «Сравнить снимки», NDVI/NDMI, «Рядом» или «С разделителем» | Одинаковые сетка, охват, отношение сторон и шкала. Пропуски видны; причины изменения не устанавливаются |
| Качество | Раскрыть «Качество данных и метод расчёта» | Пригодное покрытие, версия обработки и чувствительность к смещению границ не превращаются в уверенность модели |
| Место | Нажать внутри обводки на одном из двух снимков **или** «Использовать точку с крестиком» | Место проверено сервером, закреплено окно 60 × 60 м и его канонический ID. Опорная точка подтверждается явно, это не GPS датчика |
| Задача | «Создать задачу»; указать ответственного и вопрос; плановая дата необязательна | Сохраняются выбранные место, даты, индекс и версия основания. Задача не означает состоявшееся посещение |
| История | «Сохранить и открыть историю» | Открывается история сохранённой задачи и её места. План не создаётся автоматически |
| Результат | После настоящего посещения — «Записать результат осмотра» | Отдельный автор, фактическое время, наблюдения и исход; фото при наличии, следующий шаг. Требуется явное подтверждение реального посещения |
| Повторный визит | Снова записать результат для того же места | Новая запись дополняет историю, не переписывает предыдущую. Тексты, исходы и фото сравниваются без автоматического диагноза |

Верхняя «История» открывает журнал выбранной площади. История места связывает
посещения по `place.id`, поэтому новый вопрос для того же окна не должен создавать
несвязанную вторую историю. Номер задачи и идентификатор места имеют разное назначение.

### Данные окна и площади

Общее покрытие площади не подтверждает пригодность выбранного окна. В интерфейсе
есть отдельная сводка места. Для динамики окна нужны минимум 5 пригодных внутренних
ячеек и 80% покрытия; значения при недостатке данных остаются неизвестными.
Не заменять их нулями, интерполяцией или сводкой всей площади.

История места показывает индексы за выбранный архивный период. Посещение вне
этого периода остаётся в журнале, но не должно появляться на графике старых дат.
Крестики — пропуски, отметки смены processing baseline — смена обработки, а не болезнь.

## Демонстрация за 4–5 минут без вымышленных осмотров

Для демонстрации и репетиции использовать отдельный журнал:

```powershell
.\START_SCOUTING.cmd --port 8776 --directory data/frontend-dev-journal
```

Открыть `http://127.0.0.1:8776/scouting`. Не использовать рабочий журнал хозяйства
для QA. Новый чистый прогон — новая папка журнала; существующие записи не удалять.

1. Показать карту и сказать, что 27 обводок приблизительные. Открыть R11.
2. «Архивный пример» → «Открыть архивный пример R11». Кнопка действительно задаёт
   `recent2026`, съёмки `S2C_T37TDK_20260921T082016_L2A` и
   `S2C_T37TDK_20261014T083251_L2A`.
3. Передвинуть разделитель, переключить NDVI/NDMI, раскрыть качество. Для этой
   пары R11: ΔNDMI около **−0,119**, ΔNDVI около **−0,173**, общая пригодная доля
   около **92%**, чувствительность NDMI к рассчитанным смещениям **−0,129…−0,098**.
   Это реальное изменение поверхности на выбранной паре, не метрика качества модели.
4. «Рядом» → «Использовать точку с крестиком» → «Создать задачу». Заполнить вопрос.
   На защите можно остановиться на черновике. Для показа самого сохранения в отдельном
   журнале явно обозначить задачу как демонстрационную: ответственный
   «Команда Onlyfarms · демонстрация», цель начинается с «Демонстрация:».
   Это техническая задача, **не наблюдение агронома**.
5. После сохранения открыть основание в истории и «Посмотреть форму без записи».
   Показать пустые поля результата. В просмотре сохранение отключено и защищено
   обработчиком отправки; реальное посещение не подтверждать, факты и фото не придумывать.
6. Закрыть форму. Показать график одного места и пустую историю посещений.
   Объяснить, что после реальных выездов записи будут дополнять её по датам.

Если нужны план и выгрузка: «Включить в план выезда» → название → «Сохранить план»
→ «Скачать лист». Пустые строки фактического результата в листе не являются осмотром.

**Не смешивать пары:** начальная общая пара 26.09 → 11.10.2026 имеет 27/27 пригодных
площадей и ΔNDMI R11 около −0,077. Архивный пример 21.09 → 14.10.2026 имеет 14/27
пригодных площадей и ΔNDMI около −0,119. Число пригодных площадей не равно точности модели.
Старые материалы в `SCOUTING_DEFENSE_DEMO.md` сохранены как история; для текущего
перехода после задачи использовать этот документ и `DEFENSE_WALKTHROUGH.md`.

## План выезда

- До трёх **разных мест**, выбранных из сохранённых задач; несколько задач одного
  канонического места нельзя посчитать разными остановками.
- Порядок — последовательность выбора. Дорожная оптимизация, оценка времени пути
  и безопасный проезд через участок не реализованы.
- Название обязательно. Цель — обычный осмотр либо обследование перед установкой
  датчиков. Второй вариант добавляет вопросы для будущей проверки, а не подтверждённые
  условия монтажа или запись установки.
- Сохранённый план фиксирует ссылки/хеши задач и их основание. Работают HTML-лист,
  JSON с основанием и GeoJSON точек. Это не экспорт подтверждённых контуров полей.
- Если план сохранился, но загрузка листа не удалась, UI предлагает повторно открыть
  его из сохранённых планов. Не создавать второй план ради повторного скачивания.

## Черновики и защита от повторов

| Объект | Где хранится | Reload | После успешной записи |
|---|---|---|---|
| Черновик задачи | Память и `sessionStorage` текущего origin/вкладки | Восстанавливается при доступном хранилище | Удаляется только свой черновик, генерируется новый request ID |
| Черновик плана | Память и `sessionStorage` текущего origin/вкладки | Восстанавливаются название, цель, выбранные задачи и request ID | Сбрасывается после сохранения |
| Несохранённый результат и фото | Только память страницы, по задаче | Теряются | Сохраняется фактическая запись, черновик этого результата очищается |
| Сохранённые задачи, планы, результаты, фото | Локальный серверный журнал | Остаются при том же каталоге `--directory` | Не становятся Git-данными автоматически |
| Выбор дизайна | `localStorage`, параметр URL имеет приоритет | Восстанавливается | Не влияет на содержание журнала |

Ключ задачи включает площадь, период, обе сцены, версию, каноническое место и индекс.
Черновики разных оснований нельзя склеивать. При недоступном хранилище показывается
честное сообщение о хранении только в памяти. Токены, фото и результаты посещений
модуль `drafts.js` в `sessionStorage` не принимает.

`request_id` нужен для идемпотентности: повтор того же запроса после сбоя не создаёт
дубликат. Изменённое тело с прежним ID сервер отклоняет. Не генерировать новый ID
только потому, что HTTP-ответ задержался; не подменять серверную ошибку локальным
сообщением «сохранено». Во время записи кнопки блокируются. Изменение пары/места
требует проверить новое основание, а не сохранить прежний вопрос под новыми координатами.

## Пустые состояния и ошибки

| Ситуация | Требуемое поведение при редизайне |
|---|---|
| Нет задач/посещений/планов | Явная пустая история и следующий доступный шаг; никаких примеров, выдаваемых за настоящие записи |
| Нет общей пары или площадь непригодна | Нейтральное состояние и причина; сравнение заблокировано. Не подставлять другую пару только для выбранной площади |
| Облачная часть | Сохранить шахматную маску и отсутствие значений; маску не «улучшать» CSS-фильтрами |
| Непригодное окно при пригодной площади | Не вычислять/не показывать нулевую дельту окна; сводка всей площади остаётся отдельно |
| Архив устарел для сегодняшнего выезда | Сохранить реальные даты и архивную формулировку. Ветка не получает свежие снимки автоматически |
| Поменяли период/снимки во время загрузки | Старый ответ не перерисовывает новую площадь. До завершения общего расчёта переход к задаче/сохранение блокируется |
| Сервер/источник недоступен | Ошибка видна; не вставлять демонстрационные значения или успех сохранения. Сохранить доступный черновик |
| Перезапуск сервера | Токен меняется; обновить страницу, затем восстановить черновик задачи/плана. Не выводить токен в лог/скриншоты |
| Неверная версия основания/точка снаружи | Отказ без записи; вернуться к снимкам и подтвердить актуальное место |
| План сохранён, лист не загрузился | Открыть сохранённый план повторно; не обещать, что запись не произошла |
| Закрытие формы результата | Текст/фото остаются только в памяти текущей страницы; предупреждение о потере при reload сохранить |

## Клавиатура, телефон, оформление

- Tab/Shift+Tab и видимый фокус: меню, поиск, дата, NDVI/NDMI, режим сравнения,
  подтверждение места, задача, история, диалоги и экспорт. Не превращать кнопки в
  некликабельные текстовые элементы без доступных имён.
- `/` на карте открывает список и фокусирует поиск. `c` на сравнении переключает
  «Рядом»/«С разделителем». Escape закрывает выбор дат/сворачивает инспектор;
  диалоги сохраняют собственное поведение. Горячие клавиши не перехватывают ввод
  в input/textarea/select и не действуют поверх открытого диалога.
- Для разделителя сохранить и pointer-drag, и доступный range-контрол со стрелками.
  Кнопка «Использовать точку с крестиком» позволяет выбрать место без точного тапа.
- Проверить 1280×720, 768×900 и 390×844, а также длинный вопрос/ошибку и увеличенный
  шрифт. Нижнее действие, клавиатура телефона, инспектор, легенда и атрибуция карты
  не должны перекрывать друг друга. Проверять целые формы, а не только первый экран.
- Сохранить `prefers-reduced-motion`. Научные изображения не перекрашивать под тему,
  не обрезать через `object-fit: cover`: координаты клика зависят от их геометрии.
- Хай-тек — отдельный `hightech.css`, Атлас — прежний набор листов стилей. Переключатель
  не вызывает reload и сохраняет место/даты/текст. Проверить прямые ссылки
  `/scouting?design=hightech` и `/scouting?design=atlas`, затем переход в `/scouting/about`.
  Быстрый откат внешнего вида — Атлас; восстановление кода описано в
  [DESIGN_MODES.md](../DESIGN_MODES.md). Журналы и источники при визуальном откате не трогать.

## Чек-лист перед передачей и защитой

- [ ] Чистый журнал, исходные снимки открываются без сети после установки зависимостей.
- [ ] Общие даты совпадают в списке, карте, карточке и задаче; история привязана к прежнему `place.id`.
- [ ] Нет перехода к записи задачи до явного подтверждения места и окончания загрузки.
- [ ] Площадь и окно имеют собственные значения/пропуски; чувствительность не названа точностью.
- [ ] Задача после сохранения открывает историю, план остаётся отдельным действием.
- [ ] Preview результата не сохраняется; открытие карты/справки не создаёт событий журнала.
- [ ] Повтор записи с тем же ID не дублируется; ошибка не теряет черновик и не маскируется успехом.
- [ ] Task/plan draft переживает reload в той же вкладке; visit/photos — только закрытие формы без reload.
- [ ] План ограничен тремя уникальными местами; HTML/JSON/GeoJSON сохраняют источник и флаги ограничений.
- [ ] Работают глубокие ссылки, Назад/Вперёд, выбор площади и индекса, смена дизайна без потери контекста.
- [ ] Пройдены клавиатура, mobile, reduced-motion и ошибка сети; скриншоты показывают настоящее состояние.
- [ ] Никаких вымышленных полевых результатов, подтверждённых границ, автоматических диагнозов и процентов пользы осмотра.

После подготовки Python 3.13 и окружения проекта:

```powershell
py -3.13 -X utf8 scripts/start_scouting.py --check-only
.venv\Scripts\python.exe -X utf8 -m unittest tests.test_farm_scouting tests.test_farm_workspace tests.test_scouting_design
node --test tests/test_scouting_drafts.cjs
git diff --check
```

Эти существующие тесты проверяют реальные маски/общие пары, неизменность пустого
журнала, фиксацию основания, идемпотентность, ограничения места/плана/фото,
маршруты тем и безопасное хранилище черновиков. Node нужен для JS-проверок,
а не для запуска приложения; npm/Vite и сборки фронтенда здесь нет.
Автотесты не заменяют ручную приёмку интерфейса и тест удобства с агрономом.

Реальные результаты посещений тестируются только с разрешёнными фактическими данными.
Для инженерного теста синтетические записи допустимы в отдельном QA-журнале с явной
пометкой; они не переходят в рабочий журнал, материалы доказанной пользы или обучение.

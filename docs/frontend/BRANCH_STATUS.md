## Как переносить новую функцию

Сначала определить нужное поведение и read-only контракт, затем отдельно сверить
минимальные backend/data-зависимости. Для `review` нужны не только JS/CSS,
но и серверный allowlist/маршрут, расчёт основания и корректная версия архива.
Не копировать один фронтенд-файл и не эмулировать успешный ответ в браузере.

Ветка модели фиксирует исходники, данные и копии моделей по SHA. Массовый merge
или cherry-pick может принести ненужные исследования, изменить происхождение
архива и сломать проверку. Перед интеграцией сверять конкретный diff и запускать
обе проверки: сценарий UI и научное/проспективное сохранение инвариантов.
Обычная UX-задача такой интеграции не требует.

# Команда агентов для работы над интерфейсом

Подготовлены проектные профили Claude Code. Они помогают организовать работу,
но не являются отдельным приложением, фоновым сервисом или обещанием автономного
улучшения модели. Главная сессия и человек принимают итоговый diff.

## Роли

| Роль | Профиль | Результат | Инструменты |
|---|---|---|---|
| Координатор | Главная сессия, [CLAUDE.md](../../CLAUDE.md) + [AGENTS.md](../../AGENTS.md) | Сужает задачу, распределяет файлы, интегрирует проверки | Инструменты текущей сессии |
| Агрономический UX | [of-ux](../../.claude/agents/of-ux.md) | Препятствия пользователя, сценарий и критерии удобства | Чтение/поиск |
| Контракт и смысл данных | [of-contract](../../.claude/agents/of-contract.md) | Реальный API, масштабы, null/версии, отличие веток | Чтение/поиск |
| Frontend | [of-frontend](../../.claude/agents/of-frontend.md) | Код одного ограниченного изменения и профильные проверки | Чтение/изменения/shell |
| Приёмка | [of-qa](../../.claude/agents/of-qa.md) | Пройденные проверки, воспроизводимые дефекты, оставшиеся риски | Чтение/поиск/shell |

Профили наследуют модель текущей сессии (`model: inherit`). Нет обязательного
конкретного тарифа/модельного имени, внешнего MCP или вызова платного сервиса из
кода приложения. Ограничения файлов в тексте профиля — рабочие инструкции,
не файловая песочница. Shell у frontend/qa технически способен писать файлы.
Файлы не включают `bypassPermissions`, автоматическое принятие действий или хуки.

## Как включить

1. Открыть **корень checkout ветки интерфейса** в Claude Code.
2. Проверить наличие `CLAUDE.md`, `AGENTS.md` и `.claude/agents/*.md`.
3. Начать новую сессию; в `/agents` проверить проектные имена `of-ux`, `of-contract`,
   `of-frontend`, `of-qa`. Если сессия была открыта до добавления файлов, перезапустить её.
4. Для запуска задать роли явно в запросе, как ниже. Наличие профилей само по себе
   не запускает агентов и не подтверждает выполнение ими проверки.

Синтаксис файлов сверен с [документацией подагентов Claude Code](https://code.claude.com/docs/en/sub-agents).
`CLAUDE.md` импортирует общие инструкции строкой `@AGENTS.md`, в том числе для версий,
которые не читают AGENTS напрямую: [проектная память](https://code.claude.com/docs/en/memory).
На ноутбуке автора CLI Claude не установлен: проверены структура/YAML и ссылки,
а не фактический запуск этих профилей в Claude. Это нужно подтвердить у разработчика.

Если используется Claude в обычном веб-чате, файлы `.claude/agents` не превращаются
автоматически в работающих подагентов. Можно последовательно передать текст ролей
вручную, но не утверждать, что код и браузер проверены без соответствующих инструментов.
Для другого coding agent использовать AGENTS.md и ту же схему ролей через его
собственный механизм; наличие такого механизма проверять в текущем окружении.

## Порядок одной задачи

1. **Координатор:** фиксирует конкретную цель, затронутые экраны и критерии; сверяет
   ветку/чистоту Git и [матрицу функций](BRANCH_STATUS.md).
2. **Параллельно читают:** of-ux — путь агронома, of-contract — API и данные.
   Оба возвращают факты/гипотезы и ссылки, без изменений файлов.
3. **Один пишет:** of-frontend получает согласованный срез задачи и замечания.
   Нет двух авторов одного `app.js`/CSS в общей папке.
4. **Последовательно проверяет:** of-qa запускает подходящие проверки и доступные
   взаимодействия. Если находит дефект, возвращает его автору, затем проверяет исправление.
5. **Координатор:** смотрит итоговый diff, реальные скриншоты, список выполненных и
   невыполненных проверок, проверяет, что архив/модели/журнал не затронуты ошибочно.
   Коммит/отправка выполняются в пределах пользовательской задачи.

Для изменения одной подписи достаточно одного автора и быстрой проверки.
Для разных независимых файлов можно распределить запись, только заранее назначив
владельцев. При отдельных git worktree интеграция идёт после завершения каждого,
без параллельного cherry-pick/merge в одну рабочую папку.

## Первый запрос

Скопировать в Claude Code после checkout и запуска приложения:

```text
Работаем в J-D/frontend-handoff-dec04-2026 над /scouting.
Прочитай AGENTS.md, docs/frontend/README.md и docs/frontend/BRANCH_STATUS.md.
Сначала проверь доступные в этой ветке файлы и маршруты.

Задача: пройти путь агронома от карты и сравнения снимков до выбора места,
задачи, истории и предпросмотра результата. Найти три самых заметных
неудобства и реализовать один законченный срез улучшений.

Привлеки of-ux и of-contract для независимого чтения. Дай of-frontend
единоличную реализацию согласованного среза, затем of-qa — проверку.
Сохрани реальные архивные данные, смысл coverage/null, координаты,
маски и историю. Не меняй модель и не подменяй отсутствующий API макетом.
Технический журнал: data/frontend-dev-journal, порт 8776.

Сделай проверяемое изменение; в конце покажи diff, выполненные команды,
desktop/mobile скриншоты при наличии browser tool и оставшиеся ограничения.
Не создавай вымышленные реальные осмотры.
```

Все пути в запросе указаны относительно корня checkout.

## Запрос на конкретное UX-изменение

```text
Улучши [конкретный экран/действие] в /scouting.
Критерий: [наблюдаемое поведение и допустимое число действий].
of-contract проверяет нужные поля и ограничения; of-ux — смысл подписи
и состояния без данных; of-frontend вносит правки; of-qa проверяет путь.
Не менять научную сортировку, вычисления и шкалы. Не терять черновик,
место, выбранные даты и request_id при исправлении ошибок формы.
```

## Запрос на будущую интеграцию model → frontend

```text
Нужна интеграция [одной конкретной функции] из модельной ветки.
Прочитай docs/frontend/BRANCH_STATUS.md. Сначала сравни backend/data/UI
зависимости и текущие SHA. of-contract возвращает минимальный контракт,
пропуски и поведение при отсутствии модельного выпуска.
Переноси только необходимый срез, сохрани старые модели/протоколы и
фактический журнал. Проверь API, UI и контрольные суммы затронутых данных.
Не сливай все исследования и не эмулируй успешный прогноз во фронтенде.
```

Это отдельная задача: текущая передача не реализует такой перенос.

## Формат передачи между ролями

```text
Цель / текущая ветка и исходный commit:
Реализовано в этой ветке / отсутствует:
Факты кода (пути и строки):
Гипотезы UX:
Точный срез изменения и владелец файлов:
Контракты и состояния null/cloud/error/stale:
Критерии приёмки:
Проверенные команды / ручные действия:
Непроверенное и риски:
```

## Когда задача готова

Затронутый путь проходит целиком, включая неуспешные состояния. Пройденные проверки
воспроизводимы; снимки не ретушированы; инженерная проверка не названа исследованием
с агрономом. Публичный diff не содержит токенов, пользовательских журналов и фото.
Результат описывает поведение пользователя, а не только список изменённых CSS.

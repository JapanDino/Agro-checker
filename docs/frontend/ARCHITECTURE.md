# Карта приложения для UI-разработчика

Область передачи — `/scouting`, не весь исторический репозиторий агромоделей.
Реализация этой ветки: [scouting_server.py](../../agro_checker/scouting_server.py),
[web/scouting](../../web/scouting).

## Стек и запуск

- Python 3.13 x64; `http.server.ThreadingHTTPServer`, `argparse`, `sqlite3` из stdlib.
- NumPy, Rasterio, PyProj, Shapely и Pillow для чтения/расчёта проверенного архива.
- HTML/CSS и vanilla JavaScript, локальная копия Leaflet.
- Нет обязательного React/Vue/Vite, сборки npm, FastAPI, Postgres или облачного ML API.
- Запуск — [START_SCOUTING.cmd](../../START_SCOUTING.cmd), подготовка окружения —
  [start_scouting.py](../../scripts/start_scouting.py). Node используется для JS-тестов.

## Путь чтения

Браузер получает `state` → выбирает период/общую пару → запрашивает `workspace`
и `area` → показывает серверные PNG → получает каноническое место через `location`.
Затем UI передаёт выбранные даты и место в POST задачи. Метрики, ядро,
геопривязка, маски и проверка пригодности остаются на сервере.

`GET /api/scouting/history?place_id=…` относится к одному каноническому окну;
график всей обводки — другая пространственная сводка. Не объединять их в один ряд.
Старый ответ для площади/пары не должен перекрывать новый пользовательский выбор.

## Путь записи

`state` выдаёт локальный `token` → форма подтверждается пользователем → POST с
`X-Field-Token` и `request_id` → сервер повторно проверяет основание → событие
добавляется в SQLite. После записи UI перечитывает журнал/историю.

Задача не является посещением. Фото и результат сохраняются отдельным действием
в форме фактического осмотра. Preview не пишет в журнал. Точные форматы и
ограничения — в [API_CONTRACT.md](API_CONTRACT.md).

## Файлы и зависимость от интернета

Архивные PNG/ряды рассчитываются из включённых файлов; открытие экрана не обучает
модель и не загружает свежую сцену с внешнего сервиса. Первая установка Python-пакетов
требует интернета. Фоновые онлайн-источники, если доступны в выбранном слое карты,
не являются доказательством новой даты спутникового наблюдения.
Не добавлять внешние шрифты/CDN/scripts без учёта CSP и автономного показа.

Сервер раздаёт явный список ресурсов. Новый JS/CSS нужно внести в allowlist
используемого сервера; изменение одной папки не делает URL доступным автоматически.
Второй исторический сервер имеет свой список и требует отдельной проверки совместимости.

## Независимость от модели

В этой ветке нет серверного `/api/model/v1/inspection-priorities` и нового `/review`.
Научные оценки из старых JSON не становятся live-прогнозом при выводе на экран.
Интерфейс должен работать с пустым журналом и без запуска sklearn/joblib-обучения.
Подключение новых источников — отдельная интеграция по [BRANCH_STATUS.md](BRANCH_STATUS.md).

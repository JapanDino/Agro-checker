# Запуск и технический FAQ

Эта инструкция для `J-D/frontend-handoff-dec04-2026`. Команды выполняются из корня
своего checkout. Локальный сервер автора на 8770 может работать из другой ветки.

## Новый ноутбук с Windows

Нужны Git, Python **3.13 x64** и интернет для первой установки пакетов.
Node LTS нужен только для JavaScript-проверок; текущий UI не требует npm install/build.

```powershell
git clone --branch J-D/frontend-handoff-dec04-2026 --single-branch https://github.com/JapanDino/Agro-checker.git
cd Agro-checker
.\START_SCOUTING.cmd --port 8776 --directory data/frontend-dev-journal
```

Открой `http://127.0.0.1:8776/scouting`. Папку/окно процесса сервера оставь открытым.
Остановка — Ctrl+C в его терминале. Никаких реальных наблюдений при запуске не создаётся.
Этот запуск создаёт локальную `.venv`, устанавливает lock-зависимости и проверяет 92
архива по хешам. Старые десятки гигабайт исследовательских кэшей для `/scouting` не нужны.

Если репозиторий уже есть:

```powershell
git status --short
git fetch origin
git switch J-D/frontend-handoff-dec04-2026
git pull --ff-only
```

При собственных незакоммиченных изменениях сначала сохрани свою работу в коммите/
отдельной ветке; не используй reset/clean/force ради синхронизации.

## Проверки без сервера

```powershell
py -3.13 -X utf8 scripts/start_scouting.py --check-only
.venv\Scripts\python.exe -X utf8 scripts/verify_scouting_archive.py
.venv\Scripts\python.exe -X utf8 -m unittest tests.test_farm_scouting tests.test_farm_workspace tests.test_scouting_design
node --test tests/test_scouting_drafts.cjs
git diff --check
```

Не запускай все исторические модельные тесты и `train_*` для проверки стилей.
Ожидаются 92 проверенных архива; для осенней общей пары по умолчанию 27/27 пригодных
обводок, для весенней — 13/27. Другая явно выбранная пара может иметь другой охват.
Это пригодность источников, не точность предсказания.

## Частые проблемы

| Вопрос / симптом | Что делать |
|---|---|
| `py -3.13` не найден | Установить Python 3.13 x64; проверить `py -0p`. Bootstrap этой ветки явно проверяет minor-версию |
| Пакеты не ставятся | Сохранить сообщение pip; проверить интернет/доступ к PyPI и запустить bootstrap снова. Не отключать TLS и проверки хешей |
| Архив не найден или неверный SHA | Проверить ветку и наличие включённых `indices.npz`; повторно получить файлы из Git. Не генерировать случайную замену |
| На 8770 вижу другую карточку/даты | Открыть свой 8776, проверить рабочую папку процесса и ветку. Локальные серверы не синхронизируют checkout |
| Порт занят | Выбрать другой `--port`. Не завершать все Python-процессы на ноутбуке |
| Изменения Python не видны | Перезапустить свой сервер. Архив и некоторые результаты кэшируются в памяти |
| Изменения JS/CSS не видны | Обновить страницу, проверить путь/ветку, выбранный дизайн и наличие нового файла в server allowlist |
| Новый ресурс возвращает 404 | Добавить конкретный путь в явный список серверных ресурсов, сохранить MIME/CSP; не включать раздачу всего диска |
| API возвращает 400 | Сверить точные ключи/enum, оба `before` и `after`, длину и null-семантику. Не дописывать произвольные query-параметры |
| POST возвращает 403 | Перечитать state/токен после перезапуска сервера, проверить Host/Origin и same-origin. Токен не вшивать в код |
| Запрос прошёл, но исход неизвестен | Показать недостаточность данных. Не подставлять ноль или отрицательную метку |
| После reload пропал результат осмотра | Несохранённые visit/photos не являются sessionStorage-черновиком. Предупреждение/UX нужно проверять отдельно |
| После reload сохранилась цель задачи | Это ожидаемый task draft в этой вкладке. Это ещё не сохранённая задача |
| Нет реальных посещений | Правильное пустое состояние. Демо результата — через preview, без выдуманных записей |
| Нужны реальные фото/экспорт хозяйства | Получать отдельно с разрешением владельца; локальные журналы и private data не коммитить |
| macOS/Linux | Возможен `python3.13 scripts/start_scouting.py`, но инструкция и lock проверены на Windows; не утверждать проверку платформы без запуска |

## Свой React/Vue/другой фронтенд

Это возможная отдельная миграция, не текущее состояние проекта. Сохраняй API и
заголовок токена. Текущий backend принимает только разрешённые loopback Host/Origin.
Нужен осмысленный same-origin reverse proxy/интеграция; простое проксирование при
несовпадающем Origin может быть отвергнуто. Проверяй GET, POST и фотографии.
Не отключать защиту и не ставить `Access-Control-Allow-Origin: *` ради dev-сервера.
Для обычных UX-изменений существующий Python уже раздаёт UI и API с одного адреса.

## Как хранить и передавать работу

Код/стили/тесты и подписанные технические скриншоты можно коммитить. `.venv`,
локальный журнал, токены, private AgroMon export и настоящие фотографии — нет.
По умолчанию реальный журнал находится в `data/commission-journal`; для UI используй
отдельный `data/frontend-dev-journal` или другой явно технический путь.
Перед закрытием своей задачи проверяй `git status --short` и содержимое staged diff.

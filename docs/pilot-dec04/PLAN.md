## Решение по продукту

Цель релиза — **проверяемая помощь в выборе мест для осмотра**, с актуальными
наблюдениями, объяснением качества сигнала и обратной связью агронома. Полезность
должна подтверждаться новыми сведениями на осмотре и затратами времени, а не
величиной падения спутникового индекса.

У АгроМон уже есть осмотры, история, спутниковый мониторинг и ранжирование полей
по NDVI. На официальном сайте также заявлено бесплатное предоставление функций
сельхозтоваропроизводителям. Нашу дополнительную ценность предстоит проверить:
устойчивые локальные изменения, понятное основание короткого списка мест,
контроль недостаточности данных и оценка полезности выбранных мест относительно
обычного выбора агронома. Само наличие карты и задач этого преимущества не доказывает.

До 4 декабря работаем с отдельными слоями результата:

1. **Наблюдаемые изменения:** где, между какими датами, насколько устойчивы к маске,
   пространственному смещению и версии обработки. При отсутствии свежих пригодных
   данных — явное «недостаточно данных», без заполнения соседними датами.
2. **Предложение проверки:** место и вопрос агроному, срок актуальности, основание.
   Пока нет проверенной разметки полезности, это объяснимое правило/исследовательское
   ранжирование, не вероятность обнаружения болезни и не доказанная экономия.
3. **Прогноз индексов на 6–8 дней — отдельный эксперимент:** сохранение индекса как
   обязательная база; точечная ошибка, обнаружение снижений, ложные тревоги и ширина/
   покрытие диапазона по одним и тем же исходам. Подключение возможно только после
   заранее объявленной проверки. Слабая модель остаётся в исследовательском отчёте.

Автоматическое определение болезни, назначение СЗР, объём потерь и урожайность
не входят в обещание декабрьского релиза. Покупка датчиков не нужна для старта
сценария осмотров; достоверные местные измерения потребуют отдельной проверки.

## Как получить данные АгроМон

Официальный API предоставляется после соглашения: документацию и ключи выдают по
запросу. Открытой выгрузки частного хозяйства не найдено. Публичные демонстрационные
поля не подменяют данные партнёра. Официальные материалы описывают Excel-отчёты;
точные колонки и доступность нужных сущностей проверяются на реальном файле.
Универсальный работающий импортёр АгроМон без образца не заявляем.

Пути доступа:

- владелец аккаунта предоставляет подходящую выгрузку;
- владелец организует разрешённый доступ к своему хозяйству;
- команда получает документацию и read-only API в установленном АгроМон порядке.

Соглашение и запросы третьим лицам автоматически не отправлялись и не подписывались.
Готов [черновик запроса](AGROMON_REQUEST.md). Нужны прежде всего контуры/ID, культуры
и сезоны, факт посева/уборки, операции и существующие осмотры с датами. У каждого
вида сведений хранить план/факт и момент внесения, если они доступны. Отсутствие
времени внесения фиксировать как ограничение исторического воспроизведения.

На странице обучения опубликовано предупреждение о недоступности спутникового
сервиса; на других страницах встречаются отличающиеся сведения об ограниченном
режиме. Это требует проверки внутри конкретного аккаунта. Собственный сбор открытых
спутниковых данных должен работать независимо от доступности этого модуля АгроМон.

## Правила обучения и проверки

**Сохраняем прежнее ограничение:** настройки/кандидаты/пороги выбираются только
по 2024; 2025–2026 не используются для подбора. Ранние сезоны допускаются в обучение
после проверки совместимости. Уже просмотренные исторические годы не называются
новым слепым тестом. Новые записи ноября 2026 — проверка замороженного решения,
без дообучения и изменения порогов по их исходам.

- Разделять прошедшую дату операции, момент её внесения и доступность выгрузки.
  Ретроспективно внесённый факт не превращается в заранее доступный признак.
- Данные для прогноза ограничены моментом выдачи. Будущие осадки, будущий снимок,
  облачность будущей сцены, результаты посещения и последующий диагноз не входят во входы.
- Избегать смешения одного реального поля/эпизода между обучением и проверкой.
  Пока поля не подтверждены, группировать пространственно и по датам, обозначая
  ограничение. Десятки пикселей одной проблемы не считать независимыми событиями.
- Неизвестный/неполный/запоздавший результат остаётся неизвестным. В сравнении
  показывать и неблагоприятные сценарии неизвестности. Не обучать на отсутствии записи.
- Вероятность полезности/болезни не выводится из некалиброванного score. Пока нет
  проверенных бинарных меток, показывать основания и порядок, а не проценты вероятности.

### Качество по трём разным задачам

1. **Данные:** доля покрытых площадей, возраст последнего пригодного наблюдения,
   полнота периода, качество общих пикселей, стабильность геометрии, задержка обновления.
2. **Спектральный прогноз:** MAE относительно сохранения индекса, precision/recall
   снижений при одинаковом определении события, ложные тревоги на один выпуск,
   покрытие и ширина заявленного диапазона, отдельно на резких снижениях NDMI.
3. **Полезность осмотров:** Precision@K только по полным проверенным спискам,
   число новых обоснованных находок, затраты времени, неизвестные исходы и контроли.
   Сравнение — тот же бюджет и тот же доступный пул, включая обычный выбор агронома.

Цель — улучшение без роста ложных выборов; это условие приёмки, а не обещание,
что оно уже достижимо. Парные интервалы неопределённости считать по датам/эпизодам,
а не по независимым пикселям. При малой выборке честный вывод — «не установлено».
Предложение сократить время подготовки на 20% остаётся проверяемой гипотезой прежнего
протокола; не подменяет измеренное сравнение.

Разметка и контрольный сбор уже описаны в
[протоколе приоритета осмотров](../inspection-priority/PROTOCOL.md) и
[словаре данных](../inspection-priority/DATA_DICTIONARY.md). Новые документы не
обнуляют эти требования и не означают автоматическое обучение по заметкам.

## Если доступ/разметка не появятся

Декабрьский результат ограничиваем актуальными наблюдениями, контролем качества,
объяснимой очередью проверки и журналом. Оценку «польза агроному» оставляем гипотезой
до независимого сравнения. Доступ к АгроМон позволит убрать повторный ввод и
учесть реальные культуры/операции; он сам по себе не докажет качество модели.


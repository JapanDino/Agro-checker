# Перенос AgroPulse на новый ноутбук

Ветка `main` содержит код, текущий интерфейс, конфигурации, тесты, отчёты,
сохранённые исследовательские модели, результаты экспериментов и 92 архива
индексов Sentinel-2, необходимые для работы `/scouting`.

## Windows: первый запуск

Установите Git и Python **3.13 x64** с официальных сайтов. Затем:

```powershell
git clone https://github.com/JapanDino/Agro-checker.git
cd Agro-checker
.\START_SCOUTING.cmd
```

Первый запуск создаёт `.venv`, устанавливает зафиксированные зависимости из
интернета и сверяет контрольные суммы спутниковых архивов. Затем открывайте
<http://127.0.0.1:8770/scouting>. Окно запуска нужно оставить открытым.
Остановка: Ctrl+C. При занятом порте: `START_SCOUTING.cmd --port 8771`.

Для обновления кода остановите сервер, выполните `git pull --ff-only`, запустите
снова. При наличии собственных изменений сначала сохраните их в отдельном коммите.

## Проверка без запуска сервера

```powershell
py -3.13 scripts/start_scouting.py --check-only
.venv\Scripts\python.exe -m unittest tests.test_farm_workspace tests.test_farm_scouting
```

Ожидается 92 проверенных архива, 27/27 пригодных площадей для осенней пары
по умолчанию и 13/27 для весенней. Это полнота данных, не точность модели.
Проверка не создаёт задачи или посещения и не запускает обучение.

На macOS/Linux возможен запуск `python3.13 scripts/start_scouting.py`;
эта инструкция и зафиксированные зависимости проверены на Windows x64.

## Показ прототипа

Текущее оформление — светлый «Пульс». Кнопка «Дизайн: Пульс» в шапке переключает
Пульс → Хай-тек → Атлас без перезагрузки. [Оформления и откат](DESIGN_MODES.md).

Кнопка «Архивный пример» открывает пример R11 от 21 сентября до 14 октября 2026.
У него ΔNDMI около −0,119 и 14/27 пригодных площадей на общей паре. У исходной
пары по умолчанию 26 сентября — 11 октября другая величина: около −0,077.
Задачи, планы и история реальных посещений доступны в том же интерфейсе.
Журнал на новом ноутбуке начинается пустым.

### Перед презентацией (5 минут)

1. Остановите сервер (Ctrl+C), выполните `git pull --ff-only`, запустите `START_SCOUTING.cmd`.
   В окне должно быть «92 satellite archives verified» и адрес `http://127.0.0.1:8770/scouting`.
2. Откройте **http://127.0.0.1:8770/scouting?design=pulse** — ссылка сразу включает «Пульс»,
   даже если раньше в этом браузере было выбрано другое оформление.
3. Проверьте три экрана:
   - карта: слева карточка «Что умеет AgroPulse», справа R11, все 27 площадей видны;
   - «Возможности» в шапке → схема из презентации со статусами;
   - «Сегодня» → «Пример», дата 20.05.2024: R11 и R07 — риск, R02 и R23 — проверить,
     R01 и R09 — норма.
4. На проекторе используйте масштаб браузера 100 %. Интерфейс проверен на экранах от
   1280 × 720 до 2560 × 1440: элементы не перекрывают поля.
5. Интернет для показа не нужен: шрифт, карты, снимки и погода хранятся локально.

Что заявлено в презентации и что работает: [PRODUCT_CAPABILITIES.md](PRODUCT_CAPABILITIES.md).
Скриншоты для слайдов: [assets/slides-2026-11-08](assets/slides-2026-11-08/README.md).

Подробный [маршрут показа перед жюри](DEFENSE_WALKTHROUGH.md): после сохранения
задачи открывается история места; «Посмотреть форму без записи» позволяет показать
результат без фиктивного посещения. План выезда составляется по желанию.

## Что хранится отдельно

- Секреты, `.env`, личные документы, журналы и локальные настройки в публичный
  репозиторий не включены. Скрипты передачи файлов и временные подписанные ссылки
  также исключены.
- Виртуальные окружения и дубли ZIP/установочных сборок не нужны после клонирования.
- Сырые погодные и спутниковые кэши занимают десятки гигабайт и не входят в Git.
  Исходные конфигурации, каталоги, происхождение данных, результаты и модели
  сохранены. Для повторного запуска отдельных старых исследований могут
  понадобиться их исходные кэши и дополнительные `requirements-*.txt`.
- Работа `/scouting` со включённым архивом этих кэшей не требует.
- Собственные новые записи попадут в `data/commission-journal`, который Git
  игнорирует. Для переноса личного журнала используйте отдельную приватную копию.

Текущий продукт помогает подготовить обследование на основе архивных наблюдений.
Границы приблизительные; прогноз болезней, подключение датчиков и обучение по
осмотрам остаются задачами будущего пилота.

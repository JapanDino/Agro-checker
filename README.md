## Запуск первого эксперимента

Нужен Python 3.10 или новее. Внешние Python-зависимости и ключи API не требуются.

```powershell
python -m agro_checker run
python -m agro_checker run --offline
python -m agro_checker replay --night 2024-03-09
python -m unittest discover -s tests -v
```

Первый запуск загружает архивы; последующие используют локальный кэш с проверкой SHA-256. `--offline` запрещает загрузку. Команда `replay` выводит JSON: архивный прогноз отдельно от последующих наблюдений; единый момент вечернего предупреждения для этого эксперимента неизвестен.

Конфигурация: [config/pilot.json](config/pilot.json). Ночь определена как 19:00–09:00 по Москве, конец исключён. 0 °C — погодный порог для проверки, не агрономический порог повреждения. Фаза яблони остаётся неопределённой. Временные части: 2021–2023 — разработка, 2024 — валидация, 2025 — отложенная проверка.

Исходные архивы и URL/время загрузки/хэши находятся в `data/raw/`, таблицы — в `data/processed/`; оба каталога исключены из Git. Сводка сохранена в [docs/BASELINE_SUMMARY.json](docs/BASELINE_SUMMARY.json). API используется для некоммерческого исследования; условия сервисов указаны в [DATA.md](docs/DATA.md).

Для другого набора параметров можно передать `--config путь.json --data-dir путь`. При изменении URL существующий кэш намеренно не перезаписывается: используйте новый каталог данных. Дополнительные параметры команд доступны через `python -m agro_checker --help`.

## Один выпуск на ночь и коррекция

Для исходных GRIB-файлов нужен декодер ecCodes. В текущей папке подготовлено окружение `.venv`. На другом компьютере:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-archive.txt
.\.venv\Scripts\python.exe -m agro_checker single-run --workers 6
.\.venv\Scripts\python.exe -m agro_checker single-run --offline
.\.venv\Scripts\python.exe -m agro_checker single-replay --night 2025-03-09
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Конфигурация: [config/single_run.json](config/single_run.json). Обучение коррекции — весны 2022–2023; выбор — 2024; проверка — 2025. Вечерний расчёт задаётся в 18:00 по Москве, ночной период прежний, 19:00–09:00. Выбирается ближайшая точка NOAA GFS 0.25° без коррекции высоты. Входы коррекции — прогноз и час заблаговременности; наблюдения используются только как цели.

На отложенном сезоне 2025 (91 полная ночь, 6 холодных) выбранный сдвиг минимума −0,7829 °C снизил MAE минимума с 1,5620 до 1,4132 °C. Пропуски остались 2 из 6, ложные тревоги выросли с 0 до 1, почасовая MAE выросла с 1,3276 до 1,5821 °C. Коррекция специализируется на минимуме и пока не подтверждает улучшение обнаружения заморозков; смещение всей кривой используется только для диагностики.

Первый запуск загружает температурные сообщения (несколько GiB), а не полные глобальные файлы. Прерванная загрузка возобновляется из кэша. При наличии записанных ошибок онлайн-запуск повторяет только неудачные часы. Офлайн-запуск использует извлечённые точки с проверкой хэшей. Таблицы находятся в `data/processed/single-run/`, модель — в `models/single-run-correction.json`; эти каталоги исключены из Git.

Историческая доступность проверяется по времени записи объекта `S3 Last-Modified` с буфером 10 минут. Это косвенное свидетельство при предположении о публичном доступе к архиву тогда; точное время первой публикации не восстановлено. Даты и условия допуска сохранены отдельно. Воспроизведение явно помечает обучение, выбор модели и отложенную проверку; данные наблюдений выводятся отдельно от прогноза.

## Основная идея

Готовый прогноз погоды → ML уточняет температуру для места → агрономические правила оценивают риск для культуры и фазы развития → система предлагает применимые действия.

Пилот должен показать, что можно было предупредить **заранее**, и сравнить результат с исходным прогнозом погоды. Проверка на метеостанции не подтверждает точность прогноза температуры цветков или отдельных зон сада.
